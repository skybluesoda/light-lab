# LIGHT LAB — 로컬 비교 화면

5개 조명의 색상·밝기를 독립적으로 조절하고, 같은 설정의 Eevee·Cycles 결과를 비교하는 React + FastAPI 로컬 앱입니다. 외부 사이트에 배포하지 않았습니다.

## 실행

**일반 macOS 터미널**에서 아래 명령을 실행합니다.

```bash
cd '/path/to/light-lab' && ./start_app.sh
```

터미널을 실행한 채로 [http://127.0.0.1:8765](http://127.0.0.1:8765)에 접속합니다. 종료는 터미널에서 Ctrl+C입니다. 이 컴퓨터에 준비한 Python 환경과 이미 빌드한 React 화면을 사용하므로 실행할 때 Node가 필요하지 않습니다. Python 환경이 없으면 전용 가상 환경을 만들고 고정된 버전의 Python 패키지를 설치합니다.

Blender 경로를 직접 지정하려면:

```bash
BLENDER_BIN='/Applications/Blender.app/Contents/MacOS/Blender' ./start_app.sh
```

포트가 다른 앱에 사용 중이면 `LIGHT_LAB_PORT=8766 ./start_app.sh`로 실행하고 해당 포트에 접속합니다. 같은 데이터 폴더를 쓰는 LIGHT LAB 서버는 한 번만 실행할 수 있습니다.

## 사용 순서

1. 중앙 패널, 좌우 상단, 좌우 모서리 조명을 각각 조절합니다. 각 광원에 색상 선택·HEX 입력·밝기·켜기/끄기가 있습니다.
2. 해상도(480×360 / 960×540 / FHD 1920×1080), 공통 샘플 수(32~512), 실행할 엔진을 선택합니다.
3. **렌더링 비교하기**를 누릅니다. 실제로 끝난 엔진부터 결과가 표시됩니다. 진행 중에도 설정을 바꿀 수 있지만, 변경은 다음 작업에 적용됩니다.
4. 같은 작업의 두 이미지가 모두 생성되면 겹쳐 비교 버튼을 사용할 수 있습니다. 원본 이미지는 각 이미지에 마우스를 올렸을 때 나타나는 원본 링크로 엽니다.
5. 최근 실험을 선택하면 해당 설정과 결과를 불러옵니다. 같은 설정·코드의 완료 결과가 있으면 새로 렌더하지 않고 재사용합니다.

렌더 중에는 취소할 수 있습니다. 한 번에 하나의 Blender 프로세스만 실행하고 최대 4개 작업을 처리 중/대기 상태로 유지합니다. 오류가 나면 최근 작업과 실행 로그를 확인할 수 있습니다. 실패하거나 취소한 부분 결과를 두 엔진의 완료 캐시로 취급하지 않습니다.

시작할 때 가장 최근에 생성한 실험과 설정을 불러옵니다. 렌더 기록이 없는 경우에만 기존 Eevee 기준 이미지 하나를 표시합니다. 사용자가 일반 터미널에서 생성한 비교 결과 5건은 이미지 무결성·설정·GPU 실행 보고서 검증을 통과했습니다. 과거 라이트맵 방식으로 만든 40개 프리셋은 별도 캐시에 보존했으며, 현재 독립 조명·간접광 근사 결과와 섞지 않습니다.

## 이미지 확대와 전체 화면

결과 이미지를 클릭하면 전용 확대 창이 열립니다. 겹쳐 비교 중에는 아래의 **Eevee 확대** 또는 **Cycles 확대**를 누릅니다. 확대 창 안에서 이미 생성된 두 엔진 결과를 전환할 수 있습니다.

- **맞춤**: 이미지 전체가 창에 들어오도록 배율을 자동 조절합니다. 창 크기를 바꾸거나 전체 화면으로 전환해도 다시 맞춥니다.
- **100%**: 이미지 한 픽셀을 화면의 한 CSS 픽셀로 표시합니다. 기기의 물리 픽셀 배율과는 다릅니다.
- **+ / − 또는 마우스 휠**: 원본 크기 기준 10~400%로 확대·축소합니다. 휠은 커서 위치를 기준으로 확대합니다.
- **드래그 또는 방향키**: 이미지가 창보다 클 때 이동합니다. 빈 공간으로 완전히 밀려나지 않도록 이동 범위를 제한합니다. 터치 화면에서는 손가락 하나로 드래그하고 배율 버튼을 사용합니다.
- **전체 화면 버튼 또는 F**: 브라우저 전체 화면을 전환합니다. 지원하지 않거나 거절된 브라우저는 안내를 표시하며 확대 창을 계속 사용할 수 있습니다.
- **0**은 맞춤, **1**은 100%, **Esc**는 확대 창에서 돌아가기입니다. 브라우저 전체 화면에서는 Esc가 먼저 전체 화면을 종료할 수 있으므로 필요하면 한 번 더 누릅니다.

닫으면 원래 비교 방식과 설정을 유지하고 처음 누른 버튼으로 키보드 초점이 돌아갑니다. 확대는 저장된 원본 이미지를 표시하는 기능이며 해상도를 높이거나 새로 렌더하지 않습니다. 낮은 해상도 이미지는 크게 보더라도 새로운 세부 정보가 생기지는 않습니다.

검증: 실제 저장된 FHD 1920×1080 두 이미지로 열기, 엔진 전환, 100%와 맞춤, 배율 상·하한, 휠 확대, 드래그·방향키 이동, 전체 화면 진입, Esc·닫기 복귀, 키보드 초점 순환 및 복원을 확인했습니다. 390px와 1280px 화면에서 가로 넘침이 없었고 브라우저 오류 로그가 없었습니다. 현재 빌드를 다시 실행할 필요 없이 실행 중인 앱 페이지를 새로고침하면 적용됩니다.

## 설정 저장·파일 교환

조명 설정 아래 **SAVED LIGHTING**에서 이름을 입력하고 **현재 설정 저장**을 누릅니다. 광원 5개의 색상·밝기·켜기 상태와 해상도·샘플·실행 엔진을 함께 저장합니다. 저장한 설정 목록을 선택하면 편집 값으로 복원하며, 렌더를 실행해야 새 결과가 생성됩니다. 같은 이름으로 여러 번 저장하면 별도 항목을 추가합니다.

**JSON 내보내기**는 현재 편집 값을 파일로 저장합니다. **JSON 가져오기**는 파일의 형식과 각 설정 범위를 검증한 후 목록에 저장하고 편집 값에도 적용합니다. 임의 코드·파일 경로를 실행하지 않습니다. 잘못된 형식이나 지원하지 않는 버전은 거부합니다.

## 결과 다운로드

완료한 실험의 **결과 ZIP**을 누릅니다. 선택한 엔진의 `eevee.png`·`cycles.png`, 다시 가져올 수 있는 `settings.json`, Blender `render_report.json`, 생성 당시 시간의 `measurements.csv`를 포함합니다. 한 엔진만 실행했으면 해당 이미지 하나만 포함합니다. 누락·손상된 이미지는 완료 ZIP으로 내보내지 않습니다.

기존 실제 결과로 생성·검증한 묶음은 `exports/latest-comparison.zip`입니다. 새로 측정한 결과가 아니라 작업 `e7a5d9dbbb74497cbb96efe5e893b2e8`의 보관 파일입니다.

## 반복 성능 측정

**같은 조건으로 반복 측정** 영역의 **준비 1회 + 본측정 3회**를 누릅니다. 현재 선택한 해상도·샘플·조명을 두 엔진에 적용하여 총 네 쌍을 순서대로 새로 렌더합니다. 진행 중인 작업이 없어야 시작할 수 있고, 두 엔진을 모두 선택해야 합니다.

- 모든 실행에서 저장 결과 캐시를 건너뜁니다. 준비 1회는 통계에서 제외하고 본측정 3회의 엔진별 중앙값·최솟값·최댓값을 표시합니다.
- 실행마다 Blender 프로세스를 새로 시작하며 Eevee → Cycles 순서는 고정입니다. 준비 1회를 제외해도 열 상태·운영체제 캐시·고정 순서의 영향이 완전히 사라지지는 않습니다. 장시간 유지되는 인터랙티브 앱의 FPS를 의미하지 않습니다.
- 엔진별 렌더 호출 시간이 측정 기준입니다. 프로세스·장면 준비 등을 포함한 전체 작업 시간과 구분합니다. 같은 샘플 수가 같은 화질이나 계산량을 보장하지 않습니다.
- 실패·취소 시 남은 대기 실행을 중단하며 불완전한 세트로 요약 통계를 만들지 않습니다. 실행별 상태와 시간은 **측정 CSV**로 내려받을 수 있습니다. CSV에는 준비 실행 여부와 통계 포함 여부를 명시합니다.
- 앱을 닫았다 다시 열어도 측정 기록을 불러옵니다. 서버 종료로 중단된 실행을 자동으로 재실행하지 않습니다.

한 번만 새로 측정하려면 렌더 버튼 위의 **저장 결과 대신 새로 측정**을 체크합니다. 기본 비교 버튼은 같은 설정의 유효한 완료 결과를 재사용합니다.

이번 세션에서는 반복 작업·통계·중단 복구를 테스트용 임시 결과로 검증했습니다. 실제 GPU 반복 실행은 일반 터미널에서 확인해야 합니다. 실제 FHD 단일 비교 결과는 이후 저장된 작업 d240546d에서 확인했습니다. GPU 점검을 우회하지 않습니다.

## 비교 조건

- 장면·광원 5개·카메라·광택 석재는 고정합니다.
- Eevee: 렌더 중 Raytracing/Fast GI OFF, 공간별 소스 색상 확산을 계산하는 간접광 근사, 반사 프로브 캡처. 라이트맵·볼륨 간접광 베이크 없음.
- Cycles: 같은 광원의 물리적 반사 경로 계산. Eevee 전용 간접광 셰이더 출력과 패널 보조 광원은 사용하지 않습니다.
- 두 엔진에 같은 샘플 수를 적용하지만 같은 화질이나 계산량을 뜻하지는 않습니다. Cycles는 적응형 샘플링 OFF, denoise ON입니다.
- 엔진 옆 시간은 결과 생성 당시의 최종 렌더 호출 시간입니다. 반사 프로브 준비 등 렌더 호출 내부 준비가 포함됩니다. 전체 처리 시간에는 프로세스 시작·장면 생성·저장·검증도 포함됩니다. 저장된 결과를 볼 때도 과거 측정값임을 표시합니다.
- 해상도를 변경하면 별도 결과로 저장합니다. 기존 작업 d240546d의 실제 FHD 1920×1080, 256 samples 두 엔진 결과와 GPU 보고서 및 이미지 체크섬을 2026-11-05에 확인했습니다. 이번 이미지 확대 작업에서 Blender를 새로 실행한 것은 아닙니다.

## GPU 접근과 미리보기

현재 Codex 제한 실행 세션에서는 Metal 장치가 조회되지 않습니다. 이 환경에서 실행한 서버는 **미리보기 모드**로 표시하고 새 렌더 버튼을 비활성화합니다. API를 직접 호출해도 GPU 사전 점검에서 멈추므로 Blender 반복 충돌을 일으키지 않습니다.

실제 렌더는 앞서 성공한 것처럼 일반 macOS 터미널에서 `start_app.sh`를 실행해야 합니다. 포트에 이전 미리보기 서버가 남아 있으면 그 서버를 종료한 뒤 실행합니다. 실제 장치 확인 상태를 바꾸는 우회 옵션은 제공하지 않습니다.

## 파일

- `app/frontend/`: React 소스와 빌드된 `dist/`.
- `app/backend/`: FastAPI API와 작업 실행기.
- `app/data/jobs/<id>/`: 조명 설정, 이미지, Blender 보고서·로그, 작업 상태, `.blend`.
- `app/data/settings/`: 이름을 붙인 조명·렌더 설정.
- `app/data/benchmarks/`: 반복 측정 조건과 실행 연결 기록.
- `app/ui-stage4.png`: 설정 저장·결과 다운로드·반복 측정 화면 검증 스크린샷.
- `app/ui-preview.png`: 실제 로컬 화면 검증 스크린샷. 새로 렌더한 갤러리 이미지가 아니라 UI 미리보기입니다.

화면을 닫아도 서버가 켜져 있으면 작업은 계속됩니다. 서버를 정상 종료하면 진행 중 프로세스를 멈추고 대기 작업을 취소합니다. 비정상 종료로 남은 작업은 다음 실행에서 중단된 작업으로 표시합니다. 작업 파일을 삭제하는 화면 기능은 아직 없습니다.

## 검증 범위

- API/작업 실행기 테스트 25개, 기존 설정/캐시/간접광 근사 테스트 23개 통과(총 48개).
- 설정 저장·다운로드·재시작 복구, 잘못된 가져오기 거부, 두 이미지 ZIP, 손상 파일 거부, 새 측정의 캐시 우회, 준비 실행 제외 통계, 직렬 실행, 취소·실패 후 남은 작업 중단, 중단된 측정 복구, FHD 입력/출력 경로를 임시 테스트 데이터로 검증했습니다.
- React 프로덕션 빌드 성공. 브라우저에서 설정 저장·복원·JSON 내보내기/가져오기, 실제 두 이미지 겹쳐 비교, 실제 결과 ZIP 다운로드를 확인했습니다. 색상·해상도·샘플이 파일에서 복원됐고, ZIP 안에 두 이미지가 모두 있었습니다. 390px 너비에서 가로 넘침과 브라우저 오류가 없었습니다.
- 사용자가 생성한 실제 비교 GPU 렌더 5건의 보고서·이미지·체크섬 검증을 통과했습니다. 최신 보관 결과의 생성 당시 시간은 Eevee 1.476초, Cycles 12.300초입니다. 동일 설정 반복 측정의 통계값은 아닙니다.
- 이번 세션에서는 Blender를 실행하지 않았습니다. 실제 GPU 반복 측정은 아직 확인하지 않았습니다. FHD 단일 비교는 후속 저장 작업 d240546d의 보고서와 이미지로 확인했습니다. 테스트의 합성 결과는 임시 폴더에만 사용하며 앱의 실제 기록에 추가하지 않았습니다.

## 개발

현재 프런트엔드 버전은 React 19.3.1, Vite 7.3.7이며 `pnpm-lock.yaml`로 고정했습니다. Node가 있는 개발 환경에서:

```bash
cd app/frontend
pnpm install --frozen-lockfile
pnpm run build
```

빌드 후 FastAPI가 `dist/`를 제공합니다. Python 의존성은 `app/backend/requirements.txt`에 고정했습니다. 테스트 의존성은 `requirements-dev.txt`입니다.

```bash
python -m pytest app/backend/tests -q
```
