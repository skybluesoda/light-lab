# LIGHT LAB — 2단계: 프리셋과 사전 계산 결과 캐시

이 단계는 외부 설정, 프리셋 준비, 완성 이미지 캐시, 작업 기록을 연결합니다. React/FastAPI 화면은 다음 단계입니다. v13의 평천장·광택 석재·카메라·광원 배치는 고정했습니다.

## 전체 조명 색상 연동 수정

기존 40개는 패널만 색상을 바꾸고 코브/모서리는 고정된 따뜻한 흰색을 사용한 버전입니다. 새 기본 설정 `lighting.color_scope = "all"`은 선택한 색상을 패널·코브 Area Light 두 개·모서리 Area Light 두 개·모서리 발광 스트립 재질 모두에 적용합니다. 밝기 1~5는 기존대로 패널 발광 강도만 조절하며, 코브/모서리의 전력과 스트립 발광 강도는 유지합니다.

새 버전은 아직 **0/40개 생성**입니다. 우선 `./lab.sh prepare red-3`로 모든 광원이 붉게 바뀌는지 확인하고, 정상 결과면 `./lab.sh prepare --all`로 생성합니다. 기존 캐시 40개와 이전 압축 파일은 삭제하지 않았으며 과거의 패널 전용 버전입니다. 새 결과는 다른 캐시 키로 별도 저장됩니다. 기존 ZIP을 다시 열어도 새 색상 연동 결과로 바뀌지는 않습니다.

요청과 보고서에 `color_scope`, 네 실제 Area Light의 RGB, 스트립 발광 재질의 RGB를 기록합니다. 전체 연동을 요청했는데 흰색 광원이 남아 있으면 캐시 등록을 거부하도록 검사합니다. 테스트 18개 통과. 실제 새 베이크/렌더 및 색상 검증은 일반 터미널에서 진행해야 합니다. 이전 동작을 원하면 config의 `lighting.color_scope`를 `panel`로 명시할 수 있습니다.

## 현재 완료 상태

- 패널 색상 8종 × 밝기 5단계 = 프리셋 40개 정의.
- 새 프리셋 **40/40개 생성 완료**, 이미지 80장 검증 완료(2026-10-29). 일반 macOS 터미널에서 생성한 실제 결과를 점검했습니다. 설정·PNG 픽셀 데이터·파일 체크섬·두 엔진 완료 기록 모두 정상입니다. 상세: `stage2_audit.json`, `stage2_timings.csv`.
- 실제 v13 두 이미지를 `reference-v13` 참고 캐시로 등록했고 조회까지 확인했습니다. 기존의 Eevee 512 / Cycles 24 설정이므로 새 128 / 128 프리셋으로 간주하지 않습니다.
- 캐시 재사용·변경 감지·잘못된 결과 거부·중복 실행 방지·취소·GPU 접근 사전 점검 등의 동작 검사 16개 통과. 합성 이미지를 사용하는 검사는 임시 폴더에서만 실행하며 실제 렌더 결과로 등록하지 않습니다.
- 현재 채팅 세션에서는 Metal 장치가 보이지 않습니다. 새 실행기는 이 상태를 감지하면 Blender를 띄우기 전에 멈춰 이전의 반복 충돌 창을 방지합니다. 일반 터미널 실행이 필요합니다.

## 실제 측정 결과

40개 프리셋의 중앙값: Eevee 최종 렌더 1.231초, Cycles 11.202초, 라이트맵 사전 처리 97.178초. 모두 480×360, 128/128 samples입니다. Eevee 최종 렌더 시간에는 사전 처리 시간이 포함되지 않습니다. 저장 결과 조회는 10회 중앙값 0.437ms였으며 화면 표시 시간은 아닙니다. 빨강 밝기 3의 두 엔진 이미지는 시각적으로도 확인했습니다. 전체 이미지의 전수 시각 품질 검사를 수행한 것은 아닙니다.

## 시작

기존에 사용한 일반 macOS 터미널에서 실행합니다. Python 3.11 이상과 준비된 Blender 4.5.15 LTS를 사용합니다. 실행기 자체에는 추가 Python 패키지를 설치할 필요가 없습니다.

```bash
cd '/path/to/light-lab'

# 준비 상태 확인
./lab.sh list

# 이미 등록된 실제 참고 결과를 바로 조회
./lab.sh show reference-v13

# 먼저 하나만 생성: 옅은 파랑, 밝기 3(기존 발광 강도 3.0)
./lab.sh prepare ice-3

# 저장된 이미지 경로와 생성 당시 측정 시간 조회. Blender를 실행하지 않음.
./lab.sh show ice-3
```

`prepare ice-3`를 반복해도 설정과 코드가 같으면 캐시를 재사용합니다. `show`는 이미지 경로와 측정 기록을 출력하며 브라우저/앱 창을 자동으로 열지는 않습니다. 캐시가 없으면 종료 코드 2와 준비 명령을 안내합니다.

첫 프리셋의 두 이미지와 로그가 정상인지 확인한 뒤 전체를 준비합니다:

```bash
./lab.sh prepare --all
```

40개를 순차적으로 계산합니다. 아직 없는 설정만 생성하며 완료된 설정은 재사용합니다. 각 프리셋은 두 엔진 렌더와 라이트맵 베이크를 포함하므로 전체 준비에는 상당한 시간이 걸릴 수 있습니다. 중간에 Ctrl+C로 취소한 뒤 같은 명령으로 다시 실행하면 완료된 캐시는 건너뜁니다. 취소/실패한 개별 프리셋의 계산 자체를 이어서 재개하는 기능은 아직 없습니다.

## 프리셋 범위

색상은 모든 광원과 발광 표면에 연동합니다. 밝기 단계는 패널 발광 강도에 적용하며 코브 1800W×2와 모서리 조명 40W×2의 전력은 고정합니다. 프리셋의 색은 sRGB HEX이며 Blender 입력 전에 선형 RGB로 변환합니다.

| 색상 ID | 표시 이름 | sRGB |
|---|---|---|
| white | 흰색 | #FFFFFF |
| warm | 따뜻한 흰색 | #FFD0A0 |
| red | 빨강 | #FF4444 |
| green | 초록 | #55EE88 |
| blue | 파랑 | #4466FF |
| cyan | 하늘색 | #44DDFF |
| violet | 보라 | #B26CFF |
| ice | 옅은 파랑 | #B3DAFF |

| 밝기 단계 | 기본 강도 배수 | 실제 패널 발광 강도 |
|---|---:|---:|
| 1 | 0.25 | 0.75 |
| 2 | 0.5 | 1.5 |
| 3 | 1.0 | 3.0 |
| 4 | 1.5 | 4.5 |
| 5 | 2.0 | 6.0 |

ID는 `색상-밝기`입니다. 예: `blue-2`, `warm-5`. 밝기는 노출 슬라이더가 아니라 패널 자체 발광 강도입니다.

## 비교 조건

새 프리셋은 480×360, **Eevee 128 / Cycles 128 samples**입니다. Cycles 적응형 샘플링은 꺼 고정 샘플 설정을 사용하고 denoise는 켭니다. 동일 샘플 수가 동일 계산량이나 화질을 의미하지는 않습니다.

Eevee는 Raytracing/Fast GI OFF를 유지하며, CPU로 노이즈를 제거한 사전 계산 라이트맵과 반사 프로브를 사용합니다. Cycles는 엔진별 물리 재질 출력으로 직접 계산합니다. 정확한 비교 이름은 **래스터화 + 사전 계산 조명 대 패스트레이싱**입니다.

사전 생성할 때는 다음 비용을 구분합니다:

- `manifest.json`의 `job_seconds`: Blender 시작부터 검증 직전까지의 전체 실행 경과 시간.
- `render_report.json`의 `lightmap_bake.seconds`: UV 준비·베이크·맵 노이즈 제거·저장을 포함하는 사전 처리 시간.
- `renders[].seconds`: 엔진별 최종 렌더 호출과 PNG 저장 시간. Eevee 반사 프로브 준비도 여기에 포함됩니다.
- `eevee_bake_plus_render_seconds`: 사전 처리와 Eevee 렌더 합계. Blender 시작/최초 장면 생성은 제외합니다.

캐시 조회 시 표시하는 렌더 시간은 **생성 당시의 사전 측정값**입니다. 현재 프레임을 새로 렌더한 시간으로 표시하지 않습니다. `show --json`의 `lookup_ms`는 파일과 측정 기록을 읽는 시간이며 화면 표시나 Blender 렌더 시간이 아닙니다.

## 사용자 지정 색상과 설정

프리셋 밖의 색상은 새 작업으로 처리합니다. 한 번 생성한 같은 설정은 이후 재사용합니다.

```bash
./lab.sh render --color '#FF88AA' --level 3
```

외부 설정 파일은 `config/presets.json`입니다. 색상·밝기 단계·공통 조명 강도·해상도·엔진별 샘플·라이트맵 품질을 변경할 수 있습니다. 장면 형상·카메라·노출/색 관리·seed는 이 단계에서 고정합니다. 새 파일을 시험할 때는 전역 옵션을 명령 앞에 넣습니다:

```bash
./lab.sh --config config/presets.json prepare ice-3
```

`run.sh`도 계속 사용할 수 있지만 프리셋 캐시를 거치지 않는 수동 렌더용이며 `renders-manual/`에 저장합니다. 기존 `renders-v13/`은 덮어쓰지 않습니다. 새 기본 샘플은 128 / 128입니다.

## 추가 명령

```bash
# 렌더를 실행하지 않고 필요한 작업 확인
./lab.sh prepare --all --dry-run

# 특정 항목만 준비
./lab.sh prepare white-3 blue-3 red-3

# 새로 계산. 이전 결과는 cache/archive에 보존
./lab.sh prepare ice-3 --force

# 원본 .blend와 라이트맵을 포함한 작업 폴더도 보존
./lab.sh prepare ice-3 --keep-work

# 최근 10개 작업의 진행/완료/실패 기록
./lab.sh jobs

# 향후 UI가 읽을 JSON
./lab.sh list --json
./lab.sh show ice-3 --json
./lab.sh catalog
```

## 저장 구조와 변경 감지

- `cache/results/<hash>/`: 두 완성 PNG, 요청 설정, 렌더 보고서, 로그, 캐시 manifest.
- `cache/references/v13/`: 실제 기존 v13 참고 결과. 현재 프리셋과 분리.
- `cache/jobs/`: 작업별 상태와 실패/취소 기록.
- `cache/.staging/`: 처리 중이거나 실패한 작업의 중간 파일. 정상 완료하면 기본적으로 중간 `.blend`와 라이트맵을 제거하고 완성 이미지와 측정 기록만 남깁니다. `--keep-work`로 보존할 수 있습니다.
- `cache/catalog.json`: 마지막으로 갱신한 프리셋 준비 상태. `list`/`show`는 실제 캐시 파일을 확인하므로 이 스냅샷에만 의존하지 않습니다.

캐시 키에는 실제 색상·강도·조명·해상도·품질·Blender 버전과 장면 생성/라이트맵/노이즈 제거 코드의 지문이 포함됩니다. 설정이나 코드가 바뀌면 해당 결과를 다시 생성합니다. 렌더 도중 코드가 바뀌면 결과를 등록하지 않습니다. 두 엔진의 완료 여부, 실제 적용 설정, PNG 해상도/CRC/픽셀 데이터, 파일 체크섬을 확인한 후에만 결과를 공개합니다. 손상된 캐시는 조회하지 않습니다. 동시에 두 준비 작업이 실행되지 않도록 파일 잠금을 사용합니다.

작업이 실패하면 `lab.sh jobs`와 해당 기록의 `log` 경로를 확인합니다. Blender 경로를 직접 지정하려면 `BLENDER_BIN` 환경변수를 사용합니다. GPU 접근 문제에서 자동으로 CPU 설정으로 바꾸지는 않습니다. CPU로 비교하려면 외부 설정의 device를 명시적으로 `CPU`로 바꿉니다(Eevee 그래픽 장치 접근은 여전히 필요).
