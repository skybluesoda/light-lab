# 개발 과정

1. **절차적 장면과 실행 검증**: bpy로 콘크리트 갤러리·조형물·발광 패널을 만들고 Eevee/Cycles 저해상도 출력과 시간을 비교했다. 제한 실행 환경의 GPU 충돌을 발견해 일반 터미널 실행과 Metal 사전 점검을 도입했다.
2. **장면 디자인 반복**: 방을 넓히고 패널을 중앙의 세로 1:1.618 비율로 배치했다. 좌우 코브·모서리 매립 조명을 남기고 조형물을 제거했다. 파형 천장을 실험한 뒤 평천장·광택 석재로 정리했다.
3. **검은 벽·얼룩·노이즈 진단**: 간접광 부재와 프로브·추적·샘플의 영향을 나눠 확인했다. 단순히 샘플을 높이는 것과 조명 모델을 바꾸는 작업을 구분했다.
4. **라이트맵과 프리셋**: Cycles로 간접광을 미리 굽고 노이즈를 제거해 Eevee에서 조회했다. 8색×5밝기 프리셋 40개와 두 엔진 이미지 80개를 검증했다. 패널만 색이 바뀌던 범위를 전체 연동으로 수정했다.
5. **독립 조명 요구**: 광원별 색·세기를 독립적으로 바꾸면 조합·재베이크 비용이 커졌다. 고정 빈 갤러리용 소스별 ambient 필드와 반사 프로브를 선택했다. 실제 차폐·색 전달을 생략하는 한계를 명시했다.
6. **로컬 앱**: React/FastAPI, 대기열·취소·캐시·설정 교환·ZIP·CSV·반복 측정을 구현했다. 결과 확대·전체 화면을 추가했다.
7. **협업·발표**: 렌더링 개념과 실제 사용 기법을 구분하는 문서·발표 자료를 만들었다. GitHub용 사본은 최신 실행 설명과 과거 기록을 분리하고 개인 결과·외부 그림이 들어간 발표 파일을 제외했다.

아직 공개 웹 배포, 바운스 UI, Cycles 실제 경로 추출·시각화, 교육 효과 사용자 연구는 수행하지 않았다. 과거 문서의 상태 표시는 당시 기록이며 최신 상태로 소급 변경하지 않았다.
